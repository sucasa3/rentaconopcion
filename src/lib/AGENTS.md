# src/lib rules
- Multi-property CSV import (household-import.ts planner + import_household_batch RPC) is applied (migration 0042) and gated by HOUSEHOLD_IMPORT_ENABLED; capacity is checked under one org-level transaction lock, uploads only into the actor's own book, and enrichment holds live in the database (queue guard + enrichment_intake_holds), so flag off never releases lookups — release is explicit and visibility-checked; rollback never purges.
- Mixed-list upload uses stage_mixed_upload/approve_upload_spend (applied migration 0048), only for MIXED_UPLOAD_USER_IDS. Every added home is held until batch approval; saved-record homes receive zero-dispatch grants and paid homes count-capped grants with a dollar ceiling — uploads never authorize provider IO by themselves.
- Retained-contact reverse search uses upload-reverse modules and upload-reverse-migration.sql (applied Oct 30; tables are authenticated SELECT-only), gated by UPLOAD_REVERSE_ENABLED plus the mixed-upload allowlist and fixed test-account intersection. Atomic input-level reservations precede shared reverse-provider transport; uncertain/reserved searches never retry. Confirmed property associations use the existing org capacity lock and intake holds, leaving property spending separately approved — contact discovery must not consume profile capacity or release historical queues.
