# Home Systems written conditions

## Mobile layout
- Keep **Home Score** and **Home Systems** in their current compact side-by-side composition.
- Give each visible system one concise row: **system name on the left**, then a **colored status dot plus written condition on the right**, matching the reference image’s scan-friendly pattern.
- Preserve the current light card, restrained dividers, density, and 44px navigation target without enlarging the section.

## Condition language
- **Review soon** for a system nearing its expected service window, using amber.
- **May be due** for a system beyond its estimated service window, using red only when the canonical status supports it.
- **Record found** for other available records, using a neutral/blue treatment rather than “Good” or “Healthy.”
- Keep the existing empty state when no system evidence exists.

## Data and safety
- Derive every label from the existing canonical maintenance timeline; do not add inspections, monitoring claims, or sample conditions.
- Keep **Water Heater** separate from Plumbing.
- Do not imply Roof, HVAC, Water Heater, or Electrical is healthy merely because no issue was detected.
- Retain the source explanation on wider screens and accessible text for each status indicator.

## Verification
- Check the populated and no-record states at approximately 390px and desktop widths.
- Confirm labels do not wrap awkwardly or overflow, and that the rest of the homeowner dashboard remains unchanged.
