# SuCasa: from data platform to relationship-to-revenue platform

Goal: own the whole chain — Opportunity → Next Best Action → Outreach → Engagement → Outcome → ROI — for agents, lenders, and their shared homeowners.

Today the app detects opportunities and derives tasks, but it stops before action: there is no recommended action per opportunity, no drafted message attached to it, no open/click tracking on sent email, no outcome log, and no funnel/ROI view. This plan adds those layers on top of what already exists (opportunity scoring, campaigns, GHL sync, agent–lender connections, credits).

## Phase 1 — Next Best Action

Every open opportunity gets exactly one recommended action.

- Temperature ranking: HOT (contact today) / WARM (this week) / NURTURE, derived from score + strength + recent homeowner activity + how long since last contact.
- Action recipe per category, split by audience so an agent and an MLO see different plays on the same homeowner (agent: listing/market-update/move conversation; lender: HELOC/cash-out/refi/purchase-financing conversation).
- Each action carries: channel (Call / Text / Email), a one-line "why we're flagging them" summary built from the real signals, and a ready-to-send draft message generated by the AI assistant and cached on the opportunity.
- Client detail view gets an "Opportunity" header: score, temperature, 3–5 reasons, recommended action, and Send Email / Send Text / Call / Log outcome buttons.

## Phase 2 — Outreach + engagement tracking

- Sending from the action card creates an outreach record and pushes through the existing email + GHL path, tagged with the opportunity.
- Email open and click tracking: a tracking pixel and wrapped links on SuCasa-sent messages, handled by public endpoints, recorded per send.
- Engagement blends email opens/clicks with in-app homeowner behavior already captured (value checks, equity views, seller-intent forms).
- Engagement alert surface: "🚨 John Smith engaged — opened, clicked home value. Recommended: call now," shown on the Today screen and in the client record.
- Simple built-in follow-up cadence (Day 1 email, Day 2 text prompt, Day 5 call reminder, Day 7 follow-up, Day 14 nurture) that stops automatically when the homeowner engages or an outcome is logged.

## Phase 3 — One-tap outcomes

- Contacted and Engaged are detected automatically. Everything past that is one tap: No answer / Talked / Appointment set / Application (or Listing appointment) / Closed / Not interested.
- Outcomes are stored per opportunity with a timestamp and optional value, and mirrored into GHL so the CRM pipeline stays in sync.
- Logging an outcome closes the related task and stops the cadence.

## Phase 4 — Today screen rebuilt around results

- Header: HOT count, people ready for contact, homeowners engaged, potential pipeline value.
- Today's opportunities: 3–5 cards, each with name, temperature, why, and one recommended action button.
- Yesterday's activity: sent / opened / clicked / responded.
- Nothing else competes for attention; the existing tabs stay but the Today screen is the daily loop.

## Phase 5 — ROI funnel for managers

- Funnel view: homeowners → opportunities → contacted → engaged → conversations → appointments → applications/listings → transactions.
- Per-seat and per-branch rollups, plus estimated revenue vs. SuCasa cost and an ROI multiple.
- North-star metric shown first: revenue-producing opportunities created per seat, not homeowner count.

## Phase 6 — Shared agent + lender opportunities

- When a homeowner in a connected agent–lender pair triggers both a move signal and a financing signal, SuCasa creates one shared opportunity visible to both sides, each with their own recommended action.
- Either side can hand off ("loop in my MLO" / "loop in my agent"), which routes through the existing introduction request flow, respecting homeowner consent and the reveal rules already enforced.
- Outcomes on a shared opportunity are visible to both parties; funnel credit is attributed to both without double counting revenue.

## What we are deliberately not building

Complex white-labeling, a full CRM, drag-and-drop pipelines, autonomous AI agents, or new dashboards beyond the ones above.

## Technical notes

- New tables (all with RLS scoped to org membership + existing homeowner consent checks, plus GRANTs): `opportunity_actions` (recommended action, temperature, cached draft, per audience), `outreach_events` (send / open / click / reply, linked to campaign_sends and opportunity), `opportunity_outcomes` (one-tap stage log with timestamp and value), and a `shared_opportunities` link for the agent+lender pairing.
- Ranking and recipe logic go in a client-safe `src/lib/next-best-action.ts` alongside the existing `opportunities.ts` vocabulary; server reads/writes via new `*.functions.ts` wrappers following the current pattern.
- Draft generation reuses the existing AI usage metering and cap; drafts are cached so a card render never costs a model call.
- Open/click endpoints live under `src/routes/api/public/` with signed, opaque send tokens — no PII in the URL, no auth required, rate-limited.
- Funnel metrics come from a security-definer aggregate function so managers can roll up without broad table reads.
- All copy stays in opportunity language (never eligibility or qualification claims), matching the compliance framing already documented in `opportunities.ts`.

## Suggested sequencing

Phases 1 and 3 first (they make the product feel different immediately), then 4, then 2 (tracking infrastructure), then 5, then 6.
